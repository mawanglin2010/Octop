# 专家的技能 vs 技能包：为什么有两个入口

> fork 备忘（2026-11-18）。Octop 上游就是这样设计的，fork 不改，这里只解释怎么用。

在 Octop 里，专家能用的技能来自两类东西，分别在两个地方管理。把它们当成同一件事，就会遇到“技能包里下载了技能，专家里却选不到”的情况。

## 两类技能

| | 专家自己的技能 | 技能包 |
|---|---|---|
| 是什么 | 复制进这个专家工作区的技能，归它独有 | 一份公共的技能集合，可以给多个专家、多个用户共用 |
| 在哪管理 | 「个性化 → 技能」（页面顶部先切到这个专家） | 左侧「技能包」页 |
| 专家怎么用上 | 装进来就能用 | 编辑或新建专家时，在「技能包」下拉里**挂载整个包** |
| 粒度 | 一个一个装、改、删 | 整包挂载；不想要的技能可以在「个性化 → 技能 → 技能包」里单独关掉 |
| 更新 | 改了只影响这个专家 | 包里的技能更新后，所有挂载它的专家自动跟着用新的 |
| 打个比方 | 自己书架上的书 | 公共图书馆的借书证：选的是“借哪个馆”，不是“借哪本书” |

## 各处能选什么

| 场景 | 选整个技能包 | 选单个技能 |
|---|---|---|
| 新建专家 | 可以（「技能包」下拉） | 可以，但来源只有「技能市场」和「其他专家」，**不能从技能包里挑单个技能** |
| 编辑专家 | 可以（「技能包」下拉） | 编辑抽屉里没有入口；去「个性化 → 技能」里装或关单个技能 |
| 个性化 → 技能 | 「技能包」标签里挂载 / 卸载技能包，并逐个开关包里的技能 | 「技能市场」「WorkBuddy 技能」标签直接装进当前专家 |

编辑专家抽屉里放的都是“引用公共资源”的设置：技能包、知识库、MCP 连接器都是选一个共享资源挂上去。单个技能属于专家自己的内容，所以放在「个性化」里管。

## 怎么选

- **只给某一个专家用**：去「个性化 → 技能」，切到这个专家，在「技能市场」或「WorkBuddy 技能」里直接安装。
- **想给多个专家共用、统一更新**：在左侧「技能包」页把技能下载进某个包，再编辑要用的专家，在「技能包」里挂上这个包。
- **只想要包里的一两个技能**：挂上整个包后，在「个性化 → 技能 → 技能包」里把不要的关掉；或者用「复制技能」把它复制进专家工作区，变成专家自己的技能（之后不再跟着包更新；包的“复制策略”为“禁止复制”时不能复制）。

## 挂载技能包的前提

技能包是让专家直接读取主机上的技能包目录，所以只有专家的存储后端满足下面的条件时才能挂载，否则「技能包」下拉是灰的：

- 存储后端是本地（`local_shell` 或 `filesystem`），不是 Docker 沙箱或远程存储；
- 根目录是系统根 `/`，或者和工作区目录相同。

飞牛本地版的专家默认是本地存储、根目录 `/`，满足条件。

## 实例：2026-11-18 遇到的情况

在左侧「技能包」页，从技能市场把 `multi-search-engine` 下载进了技能包「fnos-skill」，然后在新建 / 编辑专家时找不到这个技能。原因：

- 技能进的是技能包，还没有任何专家挂载「fnos-skill」；
- 编辑专家的「技能包」下拉里列的是包名「fnos-skill」，不是技能名；
- 新建专家的「添加技能」没有技能包这个来源。

解决：编辑专家，在「技能包」里选「fnos-skill」并保存，这个技能就会出现在专家的技能列表里。
